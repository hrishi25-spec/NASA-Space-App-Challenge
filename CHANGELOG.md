# Changelog

User-facing changes, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); this project does not use semantic version tags yet.

## Unreleased

### Changed

- **The FIRMS training archive and the model checkpoint are no longer committable.** `Data Training/` is ~10 GB of local NASA area exports and `firecal/backend/model/` is derived from it, so both are ignored — the checkpoint is rebuilt by `train.py`, and the API works without it.
- `harmonize()` takes `geometry=False` for callers that only count detections, which skips the `scan`/`track`/`esfp`/`pixel_km2` columns: `train.py` reads ~126M rows and never needs them, while the upload path keeps its footprint arithmetic unchanged. The new `harmonized_daily()` is the one place the two sensors are rescaled onto each other, so the trained series and the served series are the same quantity.
- **Auto-rotate actually rotates the globe now.** It advanced a fixed 0.12° every 140 ms on a weak machine — 0.86°/s, a full revolution every seven minutes, which reads as a globe that is not moving — in 7–14 discrete jumps a second. It now turns at a real rate (6°/s, 3°/s on a weak machine) accumulated from frame times, so the speed no longer depends on the machine's timer or frame rate, and a frame that runs long contributes one clamped slice instead of teleporting the globe. It also stopped fighting the rest of the console: the drift holds while a gesture or another camera move owns the map, so **Fly to AOI**, **Globe view** and **Reset orbit** now complete while Auto-rotate is on instead of being cancelled a frame after they start, and the drift's own rotation no longer arms the adaptive-detail sampler (which used to hold the measurement window open every frame and could pin a slow machine at reduced detail for as long as the globe was turning).
- The three charts now fill the whole tab. Climatology, the Illusion diagnostic and the forecast are laid out in the panel's own pixels rather than scaled inside a fixed 720-unit box next to a 220px sidebar, so a wide window gets a wide chart, the tick labels keep their size at any width, and each chart's key facts moved into a row of cards underneath it.
- Charts are interactive: hovering draws a crosshair and a readout card beside the pointer with every series' value (exact counts where the axis is in thousands), ← / → walk that readout from the keyboard, and the forecast chart zooms — drag across the plot to select a window, use the **Window** selector for the last 90/180/365 days, or **Reset zoom**. A forecast line now starts where the observed line ends instead of dropping to zero across the days it does not cover.
- The map has a third basemap: **Vector** tiles (CARTO Dark Matter). Unlike the two Esri rasters it is geometry and labels, so coastlines and place names stay sharp however far you zoom instead of upscaling imagery — and it is the lightest of the three, so a slow connection now opens the console on it, with a `Slow link` hint explaining the choice. Every basemap remains one click away, and a failed fetch returns you to the imagery with the reason shown on the button.
- The map's view controls (Satellite/Terrain, Globe view, Fly to AOI, Reset orbit, Auto-rotate) now sit in one bottom-left column directly under the day/hotspot readout instead of in a separate cluster, and the column is lifted by the measured height of the Esri attribution notice so the two can never overlap — including when the notice wraps to several lines on a narrow window. The notice also paints above the map chrome.
- Dragging, rotating and zooming the map is cheaper on every basemap: the canvas render ratio is capped at 1.5× (1× on a low-end device), MSAA and tile crossfades are off, expired tiles are no longer re-validated mid-gesture, and repeated world copies are not drawn.
- The map now measures its own frame rate while you drag, zoom or rotate it. If a gesture is genuinely not keeping up, it drops to a 1× canvas and hides the detection points for the rest of that gesture, then restores full detail the moment you stop — so a slow machine stays responsive without ever showing you a permanently degraded map.
- Backend cold start is ~2.5 s faster and the baseline process ~87 MB lighter: scipy and scikit-learn now import on first clustering use instead of at module load.
- Repository layout follows the documented standard — reference docs moved into `docs/` ([index](docs/README.md)), decisions recorded in `docs/decisions/`, and the checks CI runs are available locally as `scripts/check.sh` / `check.bat`.

### Added

- **`firecal/backend/train.py` — the forecast model is now trained on the real archive.** `python train.py` streams every FIRMS CSV in the training directory (1,089 days, 126M detections, 10.3 GB in the reference run) and writes a checkpoint to `firecal/backend/model/`: a day-of-year seasonal shape for each 2° cell that burned on at least 25 days, plus the harmonized daily series the whole record adds up to. The archive is read in chunks, never held in memory, and reduced to 1.8 MB; **`--inventory`** lists what would be read and **`--limit`** reads only the head of each file. Training needs no GPU and about fifteen minutes on one core.
- Support for that checkpoint in `/forecast`. A frame that covers one fire season has one sample per day-of-year and cannot know its own shape, so the archive's shape is blended in — in log space, and fading out as the frame covers more years itself — before the usual rescale to the frame's recent level. The response names the model (`Seasonal climatology + archive prior`) and now carries a **`prior`** block with the cell count, the training date and the archive's average detections per cell. Without the checkpoint the endpoint behaves exactly as before, and with torch installed the same checkpoint warm-starts the LSTM instead of letting it start from noise.
- `check-spin-policy.mjs`, a prebuild guard over the globe drift: frame cadences are simulated through the same policy the map runs, so the rate is asserted to be the same at 100 fps and at 10 fps, a long frame is asserted to advance one clamped slice rather than a teleport, and the drift is asserted to hold while another camera move owns the map.
- `check-chart-fill.mjs`, a zero-dependency prebuild guard over the chart layout: it drives the same geometry functions the charts draw with and asserts the properties that are invisible until you look at a chart — the plot fills its container, the axis can never clip a percentile band, gridlines are readable round numbers, hover and the readout card stay inside the frame, a gap in a series breaks the line, and the card's CSS width matches the clamp in code.
- A **Docker image**: `docker build -t pyro-harmony . && docker run --rm -p 8000:8000 pyro-harmony`. One process, one port, nothing else to install — the console is built inside the image and served by the same server that answers the API, which now also accepts the browser's `/api/...` calls directly and runs as a non-root user with a `/meta` healthcheck.
- `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, `.editorconfig`, and the `docs/decisions/` ADR series.
