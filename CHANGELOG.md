# Changelog

User-facing changes, newest first. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); this project does not use semantic version tags yet.

## Unreleased

### Changed

- **The FIRMS archive directory is now `.data/`.** The dataset picker and training command use this directory, and Git and Docker exclude it so local exports stay out of commits and build contexts.

### Removed

- **The synthetic demo is out of the console.** There is no **Load demo** button, no *2002–2024* button and no *Load demo for …* escape hatch in any panel; the app opens on the FIRMS exports actually sitting in `.data/` and every panel's numbers come from those files. A synthetic record presented as the app's default state is the one thing a reviewer of a NASA-data challenge could dismiss the whole console for. `demo.py` and `POST /demo` are unchanged and still reachable from the API — they are the fixture the test suite is built on and the only data source a fresh clone (where the 10 GB archive is absent by design) has, so it stays a documented endpoint rather than a hidden path in the code — and the documented demo figures below remain the reference measurements the suite pins.

### Fixed

- **VIIRS S-NPP detections were being counted as their own sensor.** FIRMS names the instrument per product: the NOAA-20/21 C2 exports say `instrument = VIIRS`, the S-NPP ones say `SNPP` — a *platform*. `harmonize()` copied that string into `sensor` verbatim, so every Suomi NPP detection landed in a third sensor bucket with three quiet consequences: the illusion diagnostic splits on MODIS vs VIIRS and so never saw them at all, the per-sensor rescaling learned a ratio against a sensor that is the same instrument as VIIRS, and `_esfp` fell through to MODIS's 1 km nadir cell — giving a 375 m detection a footprint area **7.1× too large**, and the same error in HFII. Platform names are now mapped to the instrument they carry (Suomi NPP, NOAA-20, NOAA-21 are all VIIRS). This only became visible when all four platforms were merged into one record: opening one archive at a time, every file happened to look right.
- **A merged record no longer reports zeros for a question it was never asked.** The illusion panel's growth figures need detections on both sides of the 2011→2012 transition, so a modern archive (2023 onward — which is exactly what merging a current `.data/` directory produces) answered with `n/a` and no explanation. The endpoint now names the eras it needs, the days it has of each, and says the per-year bars are still real.

- **The Vector basemap no longer falls back to Satellite, and the map no longer opens on a blank well.** The console's own Content-Security-Policy named the CARTO tiles as `https://*.basemaps.cartocdn.com`, and a CSP host source of that form matches subdomains only — never the bare `basemaps.cartocdn.com` the style document is served from. The browser refused the fetch, the console fell back to imagery, and because an opening on Vector begins on a placeholder style with no raster layers in it, the fallback flipped the visibility of a layer that did not exist: a black map well under a badge reading *Satellite*. Both hosts are now named explicitly (and under `connect-src` as well as `img-src`, since MapLibre loads a tile with `<img>` or `fetch` depending on `refreshExpiredTiles`), and the fallback installs the imagery style rather than assuming it is already there. Verified end-to-end in Firefox and Chromium: Satellite → Vector stays on Vector.
- **A browser that cannot draw the map now says so.** MapLibre needs WebGL2 and throws without it (hardware acceleration off, a blocklisted GPU, a remote desktop), which left a silent black rectangle. The console probes for a context first, catches a constructor that still refuses, and puts the reason in the well — the panels, tabs and briefing keep working either way. A request the page's own policy blocks is surfaced the same way instead of only reaching devtools.
- The bottom-left readout and view-control column sat one attribution-notice height above the map's edge (40 px by default, more on a narrow window), which read as empty space under the basemap buttons. It now sits on the edge itself, and is lifted only while the *expanded* attribution notice is wide enough to reach under it.
- **The build's oversized-chunk warning means something again.** It had become permanent noise: MapLibre ships as prebundled ESM that cannot be split below 500 kB, and the `manualChunks` rule fused its entry and shared modules into one 1,031 kB vendor file — beside MapLibre's own 510 kB worker, both over Vite's line and both fetched only when the map opens. The shared module now has its own chunk (554 kB + 480 kB, downloaded in parallel rather than as one file) and `chunkSizeWarningLimit` is a real 600 kB budget sitting just above MapLibre's halves, so the warning stays armed: a charting library creeping back into the bundle still lights it up. The build log is also quiet now — `"type": "module"` (there is no CommonJS in the frontend) removes Vite's CJS-API deprecation notice and Node's re-parse warnings from the guard scripts. Verified by dropping the budget to 400 kB (warning returns) and restoring it (clean build, all four guards passed).

### Changed

- **The FIRMS training archive and the model checkpoint are no longer committable.** `.data/` is ~10 GB of local NASA area exports and `firecal/backend/model/` is derived from it, so both are ignored — the checkpoint is rebuilt by `train.py`, and the API works without it.
- `harmonize()` takes `geometry=False` for callers that only count detections, which skips the `scan`/`track`/`esfp`/`pixel_km2` columns: `train.py` reads ~126M rows and never needs them, while the upload path keeps its footprint arithmetic unchanged. The new `harmonized_daily()` is the one place the two sensors are rescaled onto each other, so the trained series and the served series are the same quantity.
- **Auto-rotate actually rotates the globe now.** It advanced a fixed 0.12° every 140 ms on a weak machine — 0.86°/s, a full revolution every seven minutes, which reads as a globe that is not moving — in 7–14 discrete jumps a second. It now turns at a real rate (6°/s, 3°/s on a weak machine) accumulated from frame times, so the speed no longer depends on the machine's timer or frame rate, and a frame that runs long contributes one clamped slice instead of teleporting the globe. It also stopped fighting the rest of the console: the drift holds while a gesture or another camera move owns the map, so **Fly to AOI**, **Globe view** and **Reset orbit** now complete while Auto-rotate is on instead of being cancelled a frame after they start, and the drift's own rotation no longer arms the adaptive-detail sampler (which used to hold the measurement window open every frame and could pin a slow machine at reduced detail for as long as the globe was turning).
- The three charts now fill the whole tab. Climatology, the Illusion diagnostic and the forecast are laid out in the panel's own pixels rather than scaled inside a fixed 720-unit box next to a 220px sidebar, so a wide window gets a wide chart, the tick labels keep their size at any width, and each chart's key facts moved into a row of cards underneath it.
- Charts are interactive: hovering draws a crosshair and a readout card beside the pointer with every series' value (exact counts where the axis is in thousands), ← / → walk that readout from the keyboard, and the forecast chart zooms — drag across the plot to select a window, use the **Window** selector for the last 90/180/365 days, or **Reset zoom**. A forecast line now starts where the observed line ends instead of dropping to zero across the days it does not cover.
- The map has a third basemap: **Vector** tiles (CARTO Dark Matter). Unlike the two Esri rasters it is geometry and labels, so coastlines and place names stay sharp however far you zoom instead of upscaling imagery — and it is the lightest of the three, so a slow connection now opens the console on it, with a `Slow link` hint explaining the choice. Every basemap remains one click away, and a failed fetch returns you to the imagery with the reason shown on the button.
- The map's view controls (Satellite/Terrain/Vector, Globe view, Fly to AOI, Reset orbit, Auto-rotate) sit in one bottom-left column directly under the day/hotspot readout instead of in a separate cluster, and the column stops where the attribution notice begins: the band beneath it is measured from the live notice and applied only while the notice is expanded far enough left to collide with the controls, so a collapsed notice leaves the controls on the map's own 12 px edge. The notice also paints above the map chrome.
- **The security policy is checked against the hosts the map really loads.** `test_security.py` walks the tile hosts named in the frontend, asserts each is allowed by the directive that governs it, and pins the rule that made the blank map possible (`*.example.com` does not cover `example.com`) — adding a basemap without allowing it in `main.py` now fails the suite instead of the browser.
- Dragging, rotating and zooming the map is cheaper on every basemap: the canvas render ratio is capped at 1.5× (1× on a low-end device), MSAA and tile crossfades are off, expired tiles are no longer re-validated mid-gesture, and repeated world copies are not drawn.
- The map now measures its own frame rate while you drag, zoom or rotate it. If a gesture is genuinely not keeping up, it drops to a 1× canvas and hides the detection points for the rest of that gesture, then restores full detail the moment you stop — so a slow machine stays responsive without ever showing you a permanently degraded map.
- Backend cold start is ~2.5 s faster and the baseline process ~87 MB lighter: scipy and scikit-learn now import on first clustering use instead of at module load.
- Repository layout follows the documented standard — reference docs moved into `docs/` ([index](docs/README.md)), decisions recorded in `docs/decisions/`, and the checks CI runs are available locally as `scripts/check.sh` / `check.bat`.

### Added

- **All the archives at once: every VIIRS and MODIS, every year, one record.** The picker grows a *Merge all 15 archives* entry (`POST /datasets/load?all=true`) that reads a bounded slice of every export in `.data/` into one dataset — on this machine's 15 files (MODIS C6.1 + VIIRS S-NPP/NOAA-20/NOAA-21, 2023-09-30 → 2026-09-22, ~125M rows) it returns **1,799,078 detections across 2023-09-30 → 2026-07-05** in ~37 s, two sensors, and a four-year calendar. The budget is split across the files **by size**, not evenly: these exports are wildly unequal (a 136 KB window beside a 1.87 GB year) and an even split would spend the budget on the small file while the large one contributed the same few thousand rows. The default budget for a merge is the store's own 2,000,000-row cap rather than the single-file 750,000, because a record meant to cover every year is the case where the cap *is* the budget. One unreadable export is skipped and named instead of sinking the other fourteen, and the Dataset panel lists what each file contributed — the totals alone would hide how uneven that split is.

- **The console opens on this machine's real archives.** `GET /datasets` walks `.data/` and `POST /datasets/load?id=…` opens one. No absolute path is ever published — the response carries an id relative to the archive root, a sensor label, whether the file is an archive or a near-real-time pull, and its size — and the load resolves that id *inside the inventory the walk produced*, so a request cannot name a file at all, let alone one outside the root. The header carries a **Local archives…** selector and the standby card lists every archive it found, so the first dataset is chosen rather than handed. With no archives present (a fresh clone, CI, the container image) the list is empty rather than an error, and the upload path is still there.
- **A multi-gigabyte archive opens as a bounded, honestly labelled slice.** These files run from 188 KB to 1.87 GB, so `/datasets/load` reads a capped number of rows (750,000 by default, clamped to the same 2,000,000 ceiling as the store) and stops at that cap: a 1.5 GB file costs about what a 50 MB one does. The rows come from up to 24 evenly spaced byte offsets across the whole file rather than from its head, because the opening fortnight of a chronological global export cannot answer a calendar question and one pass over the offsets costs the same as reading the head. Measured on two real files: a 308 MB MODIS archive → 750,000 read / 712,800 kept / ~3,830,728 rows estimated, spanning 2024-09-30 → 2025-09-17 in ~6 s; a 1,384 MB file → 750,000 read, ~16,605,695 estimated, spanning 2024-01-17 → 2024-09-20 in ~9 s. What was actually loaded is reported in `meta.load` — a fact about the dataset, so it survives a page refresh and is dropped the moment the dataset is replaced — and shown in a **Dataset** panel (file, sensor, `712,800 of ~3,830,728 rows · spread`), because the span a slice covers and the span the file holds are not the same thing and only one of them is on screen.
- **Auto-rotate turns the globe about Earth's axis, not a vertical one.** A bearing change on a level camera spins the planet like a top — the north pole stays put, and nothing in the motion says *Earth*. The drift now pitches the camera to **23.44°**, Earth's own obliquity, for as long as it runs, so the axis the globe turns about is the real one and the pole traces the small circle it traces from orbit. The camera is levelled again when the drift stops, but only if it is still the one that pitched it, so a camera the operator has since tilted by hand is left alone. `AXIAL_TILT_DEG` is pinned by the prebuild guard against the range Earth's tilt actually occupies.
- **`firecal/backend/train.py` — the forecast model is now trained on the real archive.** `python train.py` streams every FIRMS CSV in the training directory (1,089 days, 126M detections, 10.3 GB in the reference run) and writes a checkpoint to `firecal/backend/model/`: a day-of-year seasonal shape for each 2° cell that burned on at least 25 days, plus the harmonized daily series the whole record adds up to. The archive is read in chunks, never held in memory, and reduced to 1.8 MB; **`--inventory`** lists what would be read and **`--limit`** reads only the head of each file. Training needs no GPU and about fifteen minutes on one core.
- Support for that checkpoint in `/forecast`. A frame that covers one fire season has one sample per day-of-year and cannot know its own shape, so the archive's shape is blended in — in log space, and fading out as the frame covers more years itself — before the usual rescale to the frame's recent level. The response names the model (`Seasonal climatology + archive prior`) and now carries a **`prior`** block with the cell count, the training date and the archive's average detections per cell. Without the checkpoint the endpoint behaves exactly as before, and with torch installed the same checkpoint warm-starts the LSTM instead of letting it start from noise.
- `check-spin-policy.mjs`, a prebuild guard over the globe drift: frame cadences are simulated through the same policy the map runs, so the rate is asserted to be the same at 100 fps and at 10 fps, a long frame is asserted to advance one clamped slice rather than a teleport, and the drift is asserted to hold while another camera move owns the map.
- `check-chart-fill.mjs`, a zero-dependency prebuild guard over the chart layout: it drives the same geometry functions the charts draw with and asserts the properties that are invisible until you look at a chart — the plot fills its container, the axis can never clip a percentile band, gridlines are readable round numbers, hover and the readout card stay inside the frame, a gap in a series breaks the line, and the card's CSS width matches the clamp in code.
- A **Docker image**: `docker build -t pyro-harmony . && docker run --rm -p 8000:8000 pyro-harmony`. One process, one port, nothing else to install — the console is built inside the image and served by the same server that answers the API, which now also accepts the browser's `/api/...` calls directly and runs as a non-root user with a `/meta` healthcheck.
- `CONTRIBUTING.md`, `SECURITY.md`, `CHANGELOG.md`, `.editorconfig`, and the `docs/decisions/` ADR series.
- **The figures the docs quote are now checked against the code.** `scripts/check-doc-figures.py` counts the backend suite by parsing `test_*.py` — test functions with `@pytest.mark.parametrize` expanded, so no pytest run and no imports — and fails when a count in the README, CONTRIBUTING, PRD or brain disagrees with what would be collected; a tracked claim that vanishes from the docs fails too, so a number can be updated but not quietly dropped. It cross-checks names the same way: every `check-*.mjs` named in a document exists on disk, every guard is named in the README and the frontend guide, and every guard is wired into an npm script that `prebuild` chains. Zero dependencies; it runs as its own `docs` job in CI and as the first step of `scripts/check.sh` — the doc drift where the docs said 37 smoke tests while the suite collected 40 now fails a check instead of sitting there.
